# 📱 Автоматический скролл к полям с ошибками - v1.3.3

**Дата:** 4 ноября 2025  
**Компонент:** ShippingCalculatorForm.tsx  
**Платформа:** Мобильные устройства

---

## 🎯 Проблема

При работе с калькулятором на мобильных устройствах возникала следующая проблема:

1. Пользователь начинает заполнять поле "Откуда"
2. Не выбирает город из подсказок (или вообще пропускает поле)
3. Кликает на поле "Куда"
4. Открывается клавиатура, и поле "Откуда" уходит за пределы экрана
5. При попытке перейти дальше появляется ошибка валидации
6. **Пользователь не видит, где именно ошибка**, потому что поле "Откуда" скрыто

---

## ✅ Решение

Добавлен автоматический скролл к полю с ошибкой для мобильных устройств:

- При появлении ошибки валидации в полях "Откуда" или "Куда"
- Калькулятор автоматически скроллится к проблемному полю
- С отступом **10 пикселей** от верхнего края экрана
- Пользователь сразу видит, какое поле заполнено неправильно

---

## 🔧 Техническая реализация

### 1. Добавлен новый useEffect

```typescript
// 📱 Автоматический скролл к полю с ошибкой на мобильных устройствах
useEffect(() => {
  if (!isMobileDevice()) return; // Только для мобильных устройств
  
  // Скроллим к полю "Откуда" если есть ошибка
  if (fromFieldError && fromInputRef.current) {
    setTimeout(() => {
      scrollToElementWithOffset(fromInputRef.current, 10);
    }, 300); // Небольшая задержка чтобы пользователь увидел сообщение об ошибке
  }
  
  // Скроллим к полю "Куда" если есть ошибка (только если нет ошибки в поле "Откуда")
  if (toFieldError && !fromFieldError && toInputRef.current) {
    setTimeout(() => {
      scrollToElementWithOffset(toInputRef.current, 10);
    }, 300);
  }
}, [fromFieldError, toFieldError]);
```

### 2. Логика работы

#### Приоритет ошибок
- Если ошибка в поле **"Откуда"** → скроллим к нему
- Если ошибка только в поле **"Куда"** → скроллим к нему
- Если ошибки в **обоих полях** → скроллим только к "Откуда" (первое поле имеет приоритет)

#### Задержка 300ms
- Дает время пользователю увидеть всплывающее сообщение об ошибке (toast)
- Затем плавно скроллит к проблемному полю
- Улучшает UX - пользователь понимает, что произошла ошибка, а потом видит где именно

#### Только для мобильных
- Проверка через `isMobileDevice()`
- На десктопах скролл не выполняется (там проблемы нет)

## 📋 Используемые функции

### isMobileDevice()
```typescript
const isMobileDevice = (): boolean => {
  return /Android|webOS|iPhone|iPad|iPod|BlackBerry|IEMobile|Opera Mini/i.test(navigator.userAgent) 
    || window.innerWidth < 768;
};
```

### scrollToElementWithOffset()
```typescript
const scrollToElementWithOffset = (element: HTMLElement | null, offset: number = 15) => {
  if (!element || !isMobileDevice()) return;
  
  const elementPosition = element.getBoundingClientRect().top + window.pageYOffset;
  const targetPosition = elementPosition - offset;
  
  setTimeout(() => {
    window.scrollTo({
      top: targetPosition,
      behavior: 'smooth'
    });
  }, 100);
};
```

## 🎬 Сценарий использования

### Сценарий 1: Пропущено поле "Откуда"

1. Пользователь открывает калькулятор на мобильном
2. Не заполняет поле "Откуда"
3. Заполняет поле "Куда"
4. Выбирает тип перевозки
5. Нажимает "Рассчитать стоимость"
6. **Система:**
   - Устанавливает `fromFieldError = true`
   - Показывает toast с ошибкой: "• Укажите город отправления (Откуда)"
   - Через 300ms автоматически скроллит к полю "Откуда" с отступом 10px
   - Пользователь видит подсвеченное красным поле и понимает, что нужно исправить

### Сценарий 2: Город не выбран из подсказок

1. Пользователь вводит "Моск" в поле "Откуда"
2. **Не выбирает "Москва" из выпадающего списка**
3. Переходит к полю "Куда"
4. Вводит "Санкт-Петербург" и выбирает из списка
5. Нажимает "Рассчитать стоимость"
6. **Система:**
   - Устанавливает `fromFieldError = true`
   - Показывает toast: "• Выберите город отправления из выпадающего списка подсказок"
   - Через 300ms автоматически скроллит к полю "Откуда"
   - Пользователь видит поле с частично введенным городом и список подсказок

### Сценарий 3: Ошибка только в поле "Куда"

1. Пользователь правильно заполняет "Откуда" (выбирает из подсказок)
2. В поле "Куда" вводит текст, но не выбирает из подсказок
3. Нажимает "Рассчитать стоимость"
4. **Система:**
   - Устанавливает `toFieldError = true`
   - Показывает toast: "• Выберите город назначения из выпадающего списка подсказок"
   - Через 300ms автоматически скроллит к полю "Куда"
   - Пользователь видит проблемное поле

## ✨ Преимущества

### Для пользователей
1. **Не нужно искать ошибку** - система сама показывает проблемное поле
2. **Меньше фрустрации** - понятно, что именно нужно исправить
3. **Быстрее заполнение** - не нужно вручную скроллить вверх
4. **Лучше UX** - плавная анимация и понятная логика

### Для бизнеса
1. **Меньше брошенных форм** - пользователи доходят до конца
2. **Выше конверсия** - легче заполнить форму правильно
3. **Меньше поддержки** - пользователи реже запутываются

### Валидация при клике "Рассчитать"

```typescript
if (!fromCity) {
  missingFields.push("• Укажите город отправления (Откуда)");
  setFromFieldError(true);
  hasValidationErrors = true;

  missingFields.push("• Выберите город отправления из выпадающего списка подсказок");
  setFromFieldError(true);
  hasValidationErrors = true;
}
```

### Скролл при фокусе
При клике на поле также происходит скролл (уже было реализовано):

```typescript
onFocus={() => {
```
