# 🧪 A/B Тестирование калькулятора

## 📊 Описание

Реализовано A/B тестирование для калькулятора с двумя вариантами формы:

### **Вариант A** (3 шага с размытой ценой)
- **Шаг 1**: Маршрут
- **Шаг 2**: Параметры груза
- **Шаг 3**: Выбор способа получения расчёта (СМС/WhatsApp) + размытая цена
- **В параметрах**: Показывается стоимость (сначала 0₽, потом размыто на шаге 3)

### **Вариант B** (4 шага без показа цены)
- **Шаг 1**: Маршрут
- **Шаг 2**: Параметры груза
- **Шаг 3**: Ввод телефона (без выбора способа)
- **Шаг 4**: Подтверждение "Логист свяжется через 10 минут"
- **В параметрах**: НЕТ блока стоимости вообще

## 🎯 Логика назначения варианта

1. **Момент назначения**: При загрузке компонента калькулятора (сразу при открытии страницы)
2. **Распределение**: 50/50 (случайное)
3. **Сохранение**: В `sessionStorage` (живёт до закрытия вкладки)
4. **Ключ**: `ab_test_variant` (значения: 'A' или 'B')
5. **Timestamp**: `ab_test_start` (время назначения варианта)

**Преимущества такого подхода:**
- ✅ Пользователь сразу видит правильное количество стрелок шагов (3 или 4)
- ✅ Нет "прыжков" интерфейса
- ✅ Можно отслеживать полную воронку: Просмотр → Начало заполнения → Отправка

## 📤 Передача данных

### В Bitrix24
В поле `additionalInfo` добавлены:
```javascript
{
  abTestVariant: 'A' | 'B',
  abTestTimestamp: '1700000000000'
}
```

### В Яндекс.Метрику

#### При назначении варианта (загрузка страницы):
```javascript
ym(98742465, 'params', {
  ab_test_variant: 'A' | 'B',
  ab_test_assigned: '2025-11-18T10:30:00.000Z'
});
```

#### При начале заполнения формы (первый клик на поле):
```javascript
ym(98742465, 'reachGoal', 'form_start_filling', {
  ab_test_variant: 'A' | 'B'
});
```

#### При отправке формы - Вариант A:
```javascript
ym(98742465, 'reachGoal', 'form_submit_variant_a', {
  ab_test_variant: 'A',
  contact_method: 'phone' | 'whatsapp'
});
```

#### При отправке формы - Вариант B:
```javascript
ym(98742465, 'reachGoal', 'form_submit_variant_b', {
  ab_test_variant: 'B'
});
```

## 📊 Воронка конверсии

Теперь можно отслеживать **3 этапа**:

1. **Просмотр формы** (назначен вариант) - 100%
2. **Начало заполнения** (цель `form_start_filling`) - например, 60%
3. **Отправка формы** (цель `form_submit_variant_a/b`) - например, 25%

Это даёт полное понимание, на каком этапе теряются пользователи.

## 🎨 Особенности варианта A

### Размытая цена
На третьем шаге показывается:
- Размытая (blur: 8px) цена с реальными цифрами
- Размытое (blur: 4px) расстояние и срок доставки
- Объяснение: "Для предотвращения массовых автоматических расчётов на сайте, мы отправляем точную стоимость только по WhatsApp или СМС"

### После отправки контактов
- Размытие убирается
- Показывается чёткая цена
- Сообщение адаптируется под выбранный способ связи

## 🎨 Особенности варианта B

### Простой ввод телефона
- Только одно поле для ввода номера
- Без выбора способа связи
- Кнопка: "Рассчитать стоимость"

### Финальное сообщение
- Иконка телефона 📞
- "Наш логист свяжется с вами в течение 10 минут"
- Показывается введённый номер телефона
- **НЕ показывается цена**

## 📊 Анализ результатов

### В Bitrix24
Фильтруйте лиды по комментариям:
- Ищите: "🧪 A/B Тест: Вариант A"
- Ищите: "🧪 A/B Тест: Вариант B"

### В Яндекс.Метрике

#### Создайте сегменты:
1. **Вариант A**: параметр `ab_test_variant = 'A'`
2. **Вариант B**: параметр `ab_test_variant = 'B'`

#### Отслеживайте цели:
- `form_submit_variant_a` - конверсия варианта A
- `form_submit_variant_b` - конверсия варианта B

#### Метрики для сравнения:
1. **Конверсия в отправку формы** (главная метрика)
2. **Время до отправки** (как быстро пользователи заполняют)
3. **Процент отказов на каждом шаге**
4. **Качество лидов** (сколько реально дозвонились)

## 🔧 Технические детали

### Файлы изменены:
- `src/components/NewStepCalculator.tsx` - основной компонент калькулятора

### Новые функции:
- `getABTestVariant()` - определение и сохранение варианта
- `assignABTestVariant()` - назначение варианта при первом взаимодействии
- `Step3CalculateVariantA()` - шаг 3 для варианта A (с размытой ценой)
- `Step3ContactsVariantB()` - шаг 3 для варианта B (ввод телефона)
- `Step4CalculateVariantB()` - шаг 4 для варианта B (подтверждение)

### Условный рендеринг:
```typescript
if (abTestVariant === 'A') {
  // 3 шага
  if (activeStep === 2) return <Step3CalculateVariantA />;
} else {
  // 4 шага
  if (activeStep === 2) return <Step3ContactsVariantB />;
  if (activeStep === 3) return <Step4CalculateVariantB />;
}
```

## 🧹 Очистка данных теста

Для сброса варианта теста (для разработки):
```javascript
sessionStorage.removeItem('ab_test_variant');
sessionStorage.removeItem('ab_test_start');
```

## 📈 Рекомендации по тестированию

1. **Минимальная выборка**: 100 заявок на каждый вариант
2. **Срок тестирования**: 2-4 недели
3. **Статистическая значимость**: используйте калькулятор A/B тестов
4. **Сегментация**: анализируйте по типам перевозок (домашние/коммерческие)

## ⚠️ Важно

- Вариант назначается **один раз за сессию** (до закрытия вкладки)
- При повторном открытии сайта пользователь может получить другой вариант
- Все данные о варианте передаются в Bitrix24 и Яндекс.Метрику
- Размытая цена в варианте A рассчитывается при загрузке шага 3

## 🎯 Гипотезы для проверки

### Вариант A (с размытой ценой):
**Плюсы:**
- Пользователь видит, что расчёт выполнен
- Мотивация увидеть реальную цифру
- Честное объяснение причины

**Минусы:**
- Может показаться манипуляцией
- Дополнительный шаг выбора способа связи

### Вариант B (без показа цены):
**Плюсы:**
- Простота и прямолинейность
- Меньше шагов до ввода контактов
- Фокус на общении с логистом

**Минусы:**
- Нет "крючка" в виде цены
- Пользователь не знает примерную стоимость
